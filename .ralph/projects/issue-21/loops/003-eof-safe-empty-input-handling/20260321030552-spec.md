# Feature: EOF-safe empty input handling

## Description
The current `reverse.py` calls `input()` without guarding against `EOFError`. When stdin is genuinely empty (e.g., `printf '' | python3 reverse.py` or redirecting from an empty file), `input()` raises `EOFError` and the script exits with status 1 instead of printing an empty line. This violates the "handles empty input" acceptance criterion. The fix wraps the `input()` call in a try/except to treat EOF as an empty string.

## Acceptance Criteria
- [ ] `printf '' | python3 reverse.py` prints an empty line and exits with status 0
- [ ] `python3 reverse.py < /dev/null` prints an empty line and exits with status 0
- [ ] `echo "hello" | python3 reverse.py` still outputs `olleh`
- [ ] `echo "" | python3 reverse.py` still outputs an empty line
- [ ] All original acceptance criteria from the prompt remain satisfied

## Files to Modify/Create
- `reverse.py` - Wrap the `input()` call in a try/except block to catch `EOFError` and default to an empty string

## Dependencies
- Requires: Loop 1 (Reverse String Script) — the baseline `reverse.py` must exist
- Blocks: none
